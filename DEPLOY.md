# Deploying to Render

## 1. Push to GitHub
Create a new repo and push this folder (the `.gitignore` already skips `target/` and Eclipse files).

## 2. Create the services
Render dashboard > **New +** > **Blueprint** > select the repo. Render reads `render.yaml` and creates:
- `padmavathi-store` (Docker web service)
- `padmavathi-db` (PostgreSQL)

When asked for `ADMIN_INITIAL_PASSWORD`, enter a strong password. It is used once, to create the
`admin` user on the first start. Changing the variable later does not change an existing admin password.

## 3. Wait for the first deploy
The Docker build takes a few minutes. When the log shows `Started StoreApplication` and the service
is "Live", open `https://<your-service>.onrender.com`.

## 4. Copy your products over
The new database is empty. With your local copy running (`http://localhost:8080`):

    python scripts/migrate_catalog.py \
        --source http://localhost:8080 \
        --target https://<your-service>.onrender.com \
        --admin-password '<ADMIN_INITIAL_PASSWORD>'

Product photos already ship inside the app, so existing `imageUrl` values keep working.

## 5. Check
- `/` shows categories and products with images
- `/admin.html` login works; place a test order and see it in the dashboard
- `/actuator/health` returns `{"status":"UP"}`

## Environment variables
| Variable | Purpose |
|---|---|
| `SPRING_PROFILES_ACTIVE` | `prod` (set by Dockerfile and render.yaml) |
| `DB_TYPE`, `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USERNAME`, `DB_PASSWORD` | database connection (filled from the Render DB) |
| `DB_PARAMS` | optional JDBC suffix, e.g. `?sslMode=REQUIRED` for an external MySQL |
| `JWT_SECRET` | token signing key, generated by Render |
| `ADMIN_INITIAL_PASSWORD` | password for the first `admin` user |
| `SHOP_WHATSAPP_NUMBER` | digits only with country code |
| `UPLOAD_DIR` | where admin-uploaded photos are saved (default `uploads`) |

## Using MySQL instead of Postgres
Render has no managed MySQL. Use an external MySQL (Aiven, TiDB Cloud, etc.), remove the `databases:`
block and the `fromDatabase` env vars from `render.yaml`, and set `DB_TYPE=mysql`, `DB_HOST`, `DB_PORT=3306`,
`DB_NAME`, `DB_USERNAME`, `DB_PASSWORD` (and `DB_PARAMS` if the provider requires SSL) by hand.

## Free-plan limits to know about
- The web service sleeps after 15 minutes without traffic; the next visit takes about a minute.
- The free Postgres database expires 30 days after creation. Upgrade it before then.
- Photos uploaded from the admin page are stored on the instance disk and are lost on every restart or
  redeploy on the free plan. Either attach a paid persistent disk (mount at `/app/uploads`) or move uploads to
  cloud storage such as Cloudinary.
